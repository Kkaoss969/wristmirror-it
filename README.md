# 腕镜

腕镜是一款为华为手表安装本地第三方 HWT 表盘的 Android 应用，提供**直接安装**和**替换已有表盘**两种方式，支持采用兼容表盘协议的 WATCH、GT、FIT 等设备。

直接安装使用新的资源 ID；替换法更新手表上已经登记的普通表盘资源，为部分无法直接安装的新固件提供另一条路径。具体可用方式取决于设备型号、运行模式、固件和 HWT 内容，不能仅凭文件扩展名判断兼容性。

## 功能

- 通过蓝牙连接手表，按设备保存华为 ID 和连接配置，支持自动获取华为 ID、重新协议绑定与解除配对。
- 读取已安装表盘列表，支持应用、删除、直接安装及替换普通表盘。
- 导入本地 HWT，显示预览图、名称、格式、文件大小、描述版本和屏幕信息。
- 识别 BIN、XML 和兼容格式，根据可用资源准备传输内容。
- 显示设备信息、操作进度和结果，提供可查看、清空和导出的脱敏诊断日志。
- 首次使用及软件更新后显示使用说明。

## 格式与兼容范围

下表中的 XML 指 HWT 内部的完整表盘配置与资源容器，并非单个 XML 文件。

| 格式 | 识别依据 | 直接安装 | 替换已有表盘 |
| --- | --- | --- | --- |
| BIN 格式 | 含可用的 `watchface.bin`，没有通过校验的 XML 资源树 | WATCH 省电模式以及 GT、FIT 等系列，固件 `6.0.0.32` 之前 | WATCH 省电模式以及 GT、FIT 等系列的可替换普通表盘 |
| XML 格式 | 含有效的 `watchface/watch_face_config.xml` 和 `watchface/res/` 资源，不含 BIN | WATCH 全能模式 | 不支持 |
| 兼容格式 | 同时具备 BIN 和有效的 XML 资源树 | WATCH 全能模式；WATCH 省电模式以及 GT、FIT 等系列在固件 `6.0.0.32` 之前 | 使用其中的 BIN，适用范围与 BIN 格式相同 |

**WATCH 全能模式只支持直装，不支持替换。** `6.0.0.32` 之前的限制针对 WATCH 省电模式及 GT、FIT 等系列的直装，不表示替换法也具有相同版本边界。上述范围用于选择安装方式，最终接纳与显示效果仍由手表决定。

仅存在 `description.xml`、`watch_face_info.xml` 或一个内层 ZIP，不足以判定为 XML 格式。文件中同时含有两套资源，也不保证两套资源适用于同一型号或屏幕。

## 直装的原理

直接安装不覆盖选定的旧表盘，而是为本地内容分配新的资源 ID，按文件传输协议提交表盘资源，再处理手表的接收与应用回执。

1. **建立会话并读取列表。** 完成蓝牙认证与会话密钥协商，读取手表的 `0x27/0x02` 表盘列表，确认当前连接和已占用的资源 ID。
2. **准备实际载荷。** 从外层 HWT 提取 `com.huawei.watchface`。对 XML 或兼容格式，默认使用通过结构与完整性校验的内层容器原字节；仅有 BIN 时，使用提取的 `watchface.bin`。外层 HWT 本身不作为直装载荷发送。
3. **分配独立资源身份。** 本地生成首位固定为 `2` 的九位 ID，即 `200000000–299999999`，避让已安装 ID，并使用协议版本 `1.0.0`。该版本用于传输任务，与 HWT 描述文件里的版本分开管理。确认安装时会再次检查连接、列表、文件快照和 ID 冲突。
4. **提交文件。** 直装从 `0x28/0x02` 文件登记开始，无需先选取旧表盘或发起替换协商。随后使用设备分配的文件 ID，完成摘要校验、分块传输和终结回执处理。
5. **处理应用确认。** 根据设备报告处理后续应用操作。文件传输、客户端流程结束、资源进入列表以及手表实际显示是不同状态；界面完成提示不代替手表画面核验。操作后可刷新列表并在手表确认。

新资源 ID 的用途是登记本地表盘，不会改写 HWT 内的作者、配置、资源或签名内容，也不生成服务器授权。ID 首位固定为 `2` 用于避免与运动健康的部分会员资源 ID 约定冲突，不保证解决所有第三方表盘识别或恢复默认样式的问题。

## 替换法的原理

手表把普通表盘作为带有**资源 ID、协议版本和类型状态**的资源管理。文件上传和资源接纳是两个不同阶段：部分固件的普通下载流程还会检查授权、账户/设备绑定以及内容摘要。因此，把一个本地文件传完，并不意味着它会成为可使用的新表盘。

替换法使用手表上**已经登记、允许操作的普通表盘资源槽**，发起同一 ID 的新版本替换事务。在允许这种路径的固件实现中，既有资源的登记上下文可以被沿用，使无法直接安装的本地内容仍有机会通过更新已有资源完成部署。是否沿用许可缓存、内部状态或重新检查待接收资源，最终由设备固件决定。

腕镜的实际流程是：

1. **读取目标。** 通过真实表盘列表保留资源 ID、版本及原始类型位。预置、相册、视频、趣味贴纸等特殊资源不作为普通替换目标。
2. **准备 BIN。** 从 HWT 提取 `watchface.bin`，在本机冻结并校验副本。替换固定使用 BIN，不使用全能模式的 XML 容器，也不改写二进制内容。
3. **协商替换。** 捕获当前连接、目标 ID、原协议版本和载荷，确认时再次校验。将协议版本最后一个数字字段加一，以 `0x27/0x03` 的应用操作请求新版本。只有对应回包明确给出 `error=0`、`need=1`，才开始文件传输；`need=0` 时不强行上传。
4. **完成传输。** 通过 `0x28` 协议登记文件、协商传输方式，并响应摘要、分块及终结回执。任务文件名按资源 ID 与协议版本构造。
5. **核验结果。** 分别处理文件传输结果与表盘应用报告，再查询列表，核对同一 ID 的候选版本。不能仅以发送完成或进度达到 100% 判断实际显示成功。

替换会覆盖目标表盘内容。建议先在运动健康下载一个适合替换的免费普通表盘；需要恢复原内容时，可在商店仍提供该表盘的情况下重新下载。该路径不等同于关闭固件验签或为任意资源生成授权。

## 使用

1. **准备连接。** 先退出运动健康并清理其后台连接，避免同时占用手表通信通道。在设备页添加手表，使用内置获取功能或手动配置该设备的华为 ID。请核对账号信息；若手表意外提示清空数据，应取消并检查配置。
2. **连接手表。** 按手机和手表提示完成配对与认证。历史设备详情中可配置华为 ID、连接、重新协议绑定或解除配对。WATCH 切换全能/省电模式后，若原凭据不可用，可先断开连接，再重新协议绑定。
3. **导入 HWT。** 在表盘页选择本地文件，展开查看格式、预览和适用说明。导入只在本机解析，不会自动向手表传输。
4. **选择安装方式。** 直装点击“直接安装”并确认设备模式与固件；替换则选择允许覆盖的普通表盘，再点击“替换”并确认。XML 格式不能用于替换。
5. **核对结果。** 等待操作结束，刷新表盘列表，并在手表上确认显示。客户端流程结束与设备实际应用成功需分别判断。

删除操作沿用目标原 ID 和版本，完成后重新查询列表。删除或替换都不提供本地一键还原，请确认目标后再操作。

解除配对会解除手机系统配对，并清除本应用中对应设备的连接记录与凭据。系统限制直接解除时，按提示进入蓝牙设置，返回后再验证状态。清除本机记录不等于删除手表内的表盘。

## 技术说明

- **文件完整性：** 导入时检查容器路径、资源大小、XML 配置和 ZIP 成员 CRC，并为可用载荷建立带摘要的冻结快照。传输前重新验证，避免文件改变后仍使用旧任务。
- **操作归属：** 表盘操作绑定连接代次、资源 ID、协议版本与请求身份，防止设备切换、重连或旧回调影响新任务。重连不会自动续传或重复提交尚未确认的表盘安装。
- **通信与网络：** 表盘传输通过蓝牙完成。联网功能用于更新检查及用户主动打开的官方华为 ID 登录页面，不通过网络上传本地 HWT 进行安装。
- **设备信息：** 主页显示所选设备的名称、型号代码、蓝牙地址及连接时读取的信息。型号代码和序列号按设备缓存；点击可复制的信息文本即可复制。
- **诊断日志：** 设置页可查看、清空和导出日志。日志对敏感字段进行脱敏，对高频通信进行聚合，并记录最近一次连接的设备名称与固件版本。该信息不表示设备当前仍在线；新的连接开始时会重置，尚未读到的字段显示为“未知”。日志内容仍建议在分享前自行检查。
- **使用说明：** 按软件版本号与安装更新时间保存确认状态。首次安装、版本更新或同版本覆盖安装后，会在首次启动时重新显示；确认后正常重启不重复显示。
- **运行环境：** Android 8.0（API 26）及以上。蓝牙搜索与连接权限按 Android 版本申请；旧版系统搜索设备还需要定位权限。

请选用适合设备且有权使用的 HWT。不同型号、固件与运行模式的实现可能不同，项目不承诺所有设备均可安装或与运动健康保持相同行为。

## 编译

使用支持现有 Android Gradle 插件的 Android Studio，Gradle JDK 选择 **21**，安装 Android SDK **37.0** 与 Build Tools **37.0.0**。依赖和工具版本由工程配置与依赖锁声明。

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Windows 使用 `gradlew.bat` 执行相同任务。可单独运行以下检查：

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug
```

调试构建使用 Android Studio 的默认签名。发布签名可通过以下环境变量提供：

- `WRISTMIRROR_KEYSTORE`
- `WRISTMIRROR_STORE_PASSWORD`
- `WRISTMIRROR_KEY_ALIAS`
- `WRISTMIRROR_KEY_PASSWORD`

发布前请在 [app/build.gradle.kts](<app/build.gradle.kts>) 中核对版本名称和版本号。版本变化见[更新日志](<CHANGELOG.md>)。
